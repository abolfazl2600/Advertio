# Listing Lifecycle

## Core flow

```text
Register + Phone Verification
→ Post Listing
→ Complete Listing
→ Pending
→ Admin Moderation
→ Approved / Published
→ Active lifecycle
→ Expired
→ optional Extend/Renew
```

User can also:
- Boost
- mark Urgent
- deactivate Listing
- retain Listing in History

## Lifecycle model A — Early value monetization

Source defines:

### Phase 1 — Active / Early Access
- Heading: Day 1–3
- New Listing enters Early Access after publication.
- For 30 hours, Full access is limited to Early Access users.
- Users consume Coin per contact.
- After Early Access, Listing becomes free for everyone.
- Applies to:
  - Housing
  - Jobs
  - Passenger Cargo
- Other Categories are free.
- Daily report to Advertiser:
  - Views
  - Contact info views
  - Contact-method clicks
- Boost/Urgent can be used during active period.

### Phase 2 — Public publication
- Heading: Day 2–30
- Listing and Contact info become free.
- Boost can restore top placement.
- Urgent can distinguish Listing.
- Performance reports continue.

### Phase 3 — Expiry
- From Day 31
- Listing becomes Expired.
- Removed from active results.
- Extend/Renew can reactivate it.
- Reports available/sendable up to one month after Expiry.
- Afterwards reports archived/deleted per Data Retention Policy.

## Lifecycle model B — Free first, monetize later

Separate workflow:
- Day 1–3:
  - Free messages
  - Free contact info
- Day 4+:
  - Contact access = 1 Coin / Early Access
- Day 30:
  - Expired
- Telegram notifications continue up to 15 days after Expiry to encourage Extend.

> ⚠️ Source Conflict
>
> Model A monetizes the beginning of the Listing lifecycle, then makes access free.
>
> Model B makes Day 1–3 free and monetizes from Day 4 onward.
>
> Direction of monetization is therefore opposite.

> ⚠️ Source Conflict
>
> Model A uses 30 hours for Early Access, while another section describes Early Access as «یک روزه» and the lifecycle heading is Day 1–3.
>
> Source does not define one canonical duration.

> ⚠️ Source Conflict
>
> Model A expires from Day 31.
>
> Model B marks the Listing Expired on Day 30.
>
> This requires final Product decision.

## Extension

After Expiry:
- 30-day extension

First extension:
- Jobs/Social: 35 Coins
- Housing: 65 Coins

Second and later:
- Jobs/Social: 55 Coins
- Housing: 85 Coins

All amounts:
- Dynamic by Admin

## Boost

- Sample fee: 3 Coins
- Dynamic by Admin
- Returns Listing to top
- Republishes in communication/social channels

## Urgent

- Paid badge
- Visually distinguished
- Category-specific fee
- Admin configurable

## Performance reporting

Source lists:
- Views
- Contact info views
- Contact-method clicks
- Impression
- Detail View
- Contact Requests Count
- Reaching views

Daily reports/notifications are explicitly mentioned.

> ⚠️ Source Conflict
>
> One section says performance reports continue up to one month after Expiry.
>
> Another workflow says Telegram notifications continue up to 15 days after Expiry for Extend.
>
> Source does not state whether these are separate notification types or one shared duration.

## Deactivation

- User can deactivate Listing.
- Listing remains in History.

## Status conflict

> ⚠️ Source Conflict
>
> Entity status uses `Approved`.
>
> Publication workflow uses `Published`.
>
> Source does not define whether these are distinct states.
