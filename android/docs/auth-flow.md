# Android session / OTP implementation (#45)

Original overlays replace Android staging only: auth store, useSession, phone OTP, Telegram bot handoff and logout. Web/Telegram builds keep their originals. PhoneGate itself is preserved. Only server-issued claims feed presentation; the backend remains the sole authorization authority. No new auth endpoint, fake verified phone or local account is created.

SecureSession is an app-local Capacitor plugin: AES-256-GCM, AndroidKeyStore non-exportable key, app-bound AAD, random IV, AtomicFile in noBackupFilesDir. Calls require the local HTTPS WebView origin. The native installer disables Capacitor bridge logging and WebView debugging so plugin arguments/results cannot be logged by the default bridge logger. No localStorage fallback or silent browser-token migration: Android is a separate native sandbox and users sign in again. Browser auth data is not copied into a public/native build. Final storage/device hardening remains #53.

The session controller serializes durable operations; account change/logout clears cached private queries and invalidates stale login/restore results. An expired or malformed token cannot be returned by the API interceptor. Restore exposes no token until the existing profile endpoint confirms its subject; 401 clears storage, offline restore is retryable without displaying stale private data. Logout clears local state immediately and attempts server revocation with the captured old token even after state is cleared. Failed offline revocation is not claimed as server-side invalidation.

Phone OTP keeps the existing server challenge and provider contract. Bot login uses a system-browser handoff and in-memory expiring ticket/code, pauses polling in background, resumes on app-state, aborts on cancel/unmount, and ignores responses after logout. No ticket/JWT is logged or persisted. Return via app link and process-death challenge restoration remain #49; without those the user manually returns to the app and resumes polling. Account linking/duplicate prevention is server-owned and requires a real pre-existing test account.

Wiring: merge foundation #41, then run native/install.py against a disposable public mobile skeleton; the private build runner does this automatically. Public original payloads are listed in manifests/45.json; reviewed private source hashes remain external. Distribution approval is still required for a real private build.
