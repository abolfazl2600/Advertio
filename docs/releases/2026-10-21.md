## Detailed behavior and integration consequences

### Cargo and crawler — treat as a single compatible contract

- Required route fields only: `origin_country`, `origin`, `destination_country`, `destination`. `role` absent → validated stored default `traveler`, **no visible side**. Previous `sender` rows are preserved.
- `travel_date` optional. Catalog city and exact date validation still apply if values are supplied. A Cargo trip missing a date is legitimate; do not fabricate one in AI extraction, UI or delivery.
- `cargo_type` is now an **array** of zero or more selected values; accept legacy string inputs and stored values. New field type is reconciled with a migration instead of silently changing existing database field type in the seeder.
- Cargo channel/notification role filters already saved remain stored but are suspended; existing cargo-type equality filters test membership in arrays. This prevents silently dropping notifications for mixed item kinds.
- New no-role Cargo prices are **per kg**. If Telegram text quotes a flat fee, retain it in description without misrepresenting it as per-kg price. Source text is significant both to the reader and to marketplace duplicate detection.
- Ingest stays on `POST /api/ingest/leads` with an `attributesJson` **string**. Keep `autoPublish=false` on new sources, record dedup outcomes and use the same stable `(sourceName, externalId)` on retries. See full [mapping and operational rules](../../09-crawler/advertio-integration-2026-10-21.md).

### Photo publication and lifecycle

- A listing with a photo gets one Telegram **photo** post carrying original caption/buttons; no image yields a text post. For crawler media only the small thumbnail exists. Fallback to text is safe **only** after a definite refused photo.
- Publication history now reports partial success (text sent because Telegram rejected photo) with stored reason. Do not interpret a network failure as proof no photo was published.
- Deactivated or expired listing channels retain their historical message. Their Mini App links show “no longer available” after a `410`, without leaking internal takedown details. Source deletion still requires the crawler ingest DELETE route if the original Telegram post disappears.

### First / additional user-created listings

- The first eligible live listing in a category occupies a **free-slot** classification, but normal configurable creation charges may still apply. Any additional simultaneous owner-created listing is separately chargeable according to the policy key `{slug}.price.additional_listing`.
- The quote response is authoritative, not the browser's cached amount. The server validates before charging; a duplicate client submission uses the same key, avoiding a second debit; wallet concurrency uses PostgreSQL row-version protection.
- Extra listing charges and normal posting charges are recorded as separate idempotent service references and reconciled if a listing write never completes. No-config/zero/off **blocks** second listing publication.
- This billing flow applies to **native** Housing/Jobs/Cargo publication. Do not apply it to external `supplySource=Crawled` ingest or infer that crawler-imported records consume a user's free slot.

### Bot global search

- Both menu Search Listings and `/search` open a query prompt; `/search phrase` searches immediately. Each search word must match somewhere across title, description, location, or the bilingual category/city catalog; words are combined by AND.
- Active feed visibility/order and Saved Search matching share the keyword interpretation. Results show count and up to 5 listings/page with a Mini App link each. Category-specific advanced filtering remains in the Mini App.
- The old wizard state is intentionally retired; button/state migration falls back to a fresh search prompt. Saved searches are still supported: Save this Search creates a keyword-only Instant alert.
