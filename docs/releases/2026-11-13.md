## Executive summary

The material changes since the October 21 documentation baseline are:

1. Owners can edit native listings and inspect per-listing performance.
2. Active paid boosts are visibly distinguished on listing cards.
3. Cargo route geography expanded from seven to eleven countries, with four additional route currencies.
4. Identity-verification payment handling gained bounded retries for a concurrency race.
5. The Web app gained five-language localization, Persian RTL and a shared locale with Telegram.
6. Gate A user acquisition metrics now count phone-verified accounts and first successful phone verification.
7. The public landing page and Apps Hub were separated, with journey URLs moved under `/apps/`.
8. Instagram comment/DM automation and its Backoffice surface were introduced, but the seeded rule remains disabled and in dry-run.

## 1. Owner listing edit and performance — MR !47

[Merge Request !47](https://gitlab.com/advertio/platform/advertio-monorepo/-/merge_requests/47) adds owner actions across Housing, Cargo and Jobs.

### Edit

- A native listing owner sees **Edit** and **Performance** actions instead of the public contact call to action.
- Only the authenticated publisher can edit. Another user's listing is returned as not found, avoiding disclosure of listing ownership.
- Editable data includes title, description, category attributes, location and media.
- The listing's category, publisher and supply source cannot be changed.
- The server validates edits against the listing's existing category schema and validates media-key ownership.
- Editing does not charge coins.
- A changed Active listing is moved back to PendingReview and leaves the public feed until moderation approves it again.
- A changed PendingReview listing remains in review. An unchanged edit is a no-op.
- Crawled listings cannot be edited through this flow. Expired listings must be renewed before editing; other non-editable lifecycle states are rejected.

### Performance

The owner-only performance report is available for a listing in any lifecycle status, but only to its publisher. The owner can choose Since publication, 30 days or 7 days. The requested period never begins before the listing's publication date.

| Metric | Definition |
|---|---|
| Impressions | Not tracked; the UI reports unavailable rather than showing a misleading zero |
| Detail views | Distinct signed-in people who opened the listing, excluding the owner and anonymous visitors |
| Message taps | Count of “Message Advertiser” taps, including signed-out taps; not unique people |
| Contact requests | Distinct people who asked to contact the owner |
| Contacts made | Distinct people who successfully reached contact, paid or free |

The page includes a daily detail-view/contact chart. Opening the performance report does not itself create a listing-view event.

### Boost badge

Cards across Housing, Cargo and Jobs now show an amber **Boosted** badge only while the boost window is active. It is deliberately separate from the phone-verified shield and the Urgent flag: it communicates paid reach, not trust. The active state follows the boost end time, not only the stored flag that may await the next lifecycle-worker pass.

## 2. Cargo route geography and currencies — MR !48

[Merge Request !48](https://gitlab.com/advertio/platform/advertio-monorepo/-/merge_requests/48) expands the catalog to 11 countries and 205 seeded cities across the route catalog.

The four added countries are:

- United Arab Emirates — AED
- China — CNY
- Turkey — TRY
- Russia — RUB

The existing route countries remain Iran, Canada, United States, Germany, Italy, United Kingdom and France. The Mini App derives currency from route geography; channel-post formatting preserves the route currency instead of falling back to CAD.

Related changes also improve Cargo notification formatting: origin/destination details and applicable phone-verification / identity-verification labels are included as distinct signals. Cargo feed results expose the matching trip count, and trips with a specified past travel date are excluded by the feed API without changing the listing's stored lifecycle status.

Source commits: [route-country expansion](https://gitlab.com/advertio/platform/advertio-monorepo/-/commit/3f68f44461dd808ac2cbd18b8c278b05102227d5) · [Cargo notification formatting](https://gitlab.com/advertio/platform/advertio-monorepo/-/commit/f279fab8570f81ac3cb7f738d4cc9ee5452ed634).

## 3. Identity-verification payment concurrency — MR !49

[Merge Request !49](https://gitlab.com/advertio/platform/advertio-monorepo/-/merge_requests/49) fixes a race when a user taps Pay twice and the wallet debit and request-paid state update overlap.

The second payment-state transition now uses two retries. This handles the competing transaction outcome without surfacing the intermittent conflict as an HTTP 500. The intended invariant remains one successful charge for one verification request.

Source commit: [identity verification retry correction](https://gitlab.com/advertio/platform/advertio-monorepo/-/commit/eb882a766847a63660bda587ed54349e79249d4e).

## 4. Web localization and Gate A user counts — MR !50

[Merge Request !50](https://gitlab.com/advertio/platform/advertio-monorepo/-/merge_requests/50) adds Web localization aligned with the Telegram bot.

### Supported locales

| Locale | Language | Direction |
|---|---|---|
| `fa-IR` | Persian | RTL |
| `en-CA` | English | LTR |
| `fr-FR` | French | LTR |
| `ru-RU` | Russian | LTR |
| `hi-IN` | Hindi | LTR |

The first-visit language picker appears before the rest of the site when neither an account locale nor a browser-stored locale is available. Locale priority is the authenticated account, then browser storage, then the picker. Profile language changes are stored in the browser and, for signed-in users, on the account's shared User.Locale field. Telegram uses the same field, so an explicit language choice is shared between Web and bot.

Persian uses RTL layout. The other four locales use LTR. Static Web UI strings and API error codes are localized; user-authored listing titles and descriptions are not machine-translated. Category attribute/location labels use Persian labels when the API supplies them; otherwise English is the fallback.

### Gate A user acquisition metrics

The user-count definition changed from account creation to phone verification:

- **Total users:** distinct accounts with a successfully verified phone number, platform-wide. Active and disabled accounts count; unverified accounts and crawler publishers do not.
- **New users:** distinct accounts whose first successful phone verification falls inside the selected time window.
- Account creation, a plain bot start, Telegram group joins and chat_member updates do not count as a new verified user.
- Re-verifying the same account does not count it again or move its first-verification date into a later window.
- Active users remain based on qualifying account activity or a user-created listing during the selected window. User population metrics remain platform-wide, not category-scoped.

The new FirstPhoneVerifiedAtUtc field records the first successful verification. For accounts already verified before the field existed, the system retains the timestamp available at migration time; it does not invent an earlier date.

The bot also stops treating group-join updates as user onboarding or user-count events.

## 5. Public landing page and journey URL structure — MR !51

[Merge Request !51](https://gitlab.com/advertio/platform/advertio-monorepo/-/merge_requests/51) changes the public Web entry point and journey routing.

| Route | Purpose |
|---|---|
| `/` | Public Landing page / product introduction |
| `/apps` | In-app category directory (Hub) |
| `/apps/housing` | Housing journey |
| `/apps/passenger-cargo` | Cargo journey |
| `/apps/jobs` | Jobs journey |
| `/apps/<slug>/new` | Create form for a journey |
| `/apps/<slug>/:id` | Listing detail |

The Landing page introduces Advertio, shows the live journey directory, and links to Apps and Search. The Apps Hub is now the category directory and the Apps tab destination. The public Landing page and journey screens hide the bottom tab bar.

The old root-level journey paths (such as `/housing`) are not retained as redirects. Published links and external campaigns must use the new `/apps/` paths.

Architecture decision: [ADR 0014 — Journey paths under /apps/](../adr/ADR-0014-journey-apps-prefix.md).

## 6. Instagram automation — MR !51

MR !51 adds an Instagram automation module inside the Advertio API. It is not a separate service.

### Implemented code surface

- Meta webhook verification and signed event ingestion.
- Idempotent webhook-event storage and a background processing worker.
- Rule matching for comments, direct messages and postbacks.
- Exact, contains, any-keyword and all-keyword matching modes.
- Cargo, Housing and Jobs conversation flows; only the Cargo Reel rule is seeded.
- Private replies to comments, followed by a separate public confirmation only when the private reply succeeds.
- Direct-message conversations with pause, human hand-off and resume modes.
- Advertio redirect links that record clicks and add UTM parameters.
- Backoffice diagnostics, rule status, conversations, execution history and analytics.

### Meta authentication model

The module uses the Instagram API with Unified Login through graph.facebook.com. The documented permissions are instagram_basic, instagram_manage_comments and instagram_manage_messages. It does not use graph.instagram.com or the Instagram Login instagram_business_* permission family.

Access tokens are supplied through server environment configuration. The API does not return token values through diagnostics or persist OAuth access tokens in the database.

### Operational status and safety boundaries

- The seeded rule, **Cargo Reel - Comment to DM**, is disabled and in dry-run.
- Do not enable it until the Meta app, professional account, system-user token, webhook subscription, permissions, public site URL and actual Reel media id are configured and verified.
- Meta dashboard setup, Business Verification and App Review are manual external steps; this repository does not establish that they are complete.
- Historical comments are not bulk-scanned. A single historical comment can be previewed and sent only through the explicit confirmation endpoint and within the allowed seven-day window.
- Private-reply sends that may already have been accepted are not blindly retried after an uncertain outcome.
- Link clicks are counted. Registrations and listing creation are not yet attributed to Instagram.
- A successful webhook or merged code does not prove live Instagram delivery.

Operational documentation: [Architecture](../instagram-automation/ARCHITECTURE.md) · [Meta setup](../instagram-automation/META-SETUP.md) · [Operations](../instagram-automation/OPERATIONS.md).
